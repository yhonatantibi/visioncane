# VisionCane - אפליקציית ניסוי לזיהוי מקומי

גרסה ראשונה של קוד האפליקציה לאייפון ולאנדרואיד. המטרה: לבדוק על iPhone 13 ועל מכשיר Android אם זיהוי עצמים מקומי מהמצלמה מהיר ויציב מספיק להמשך הפרויקט.

## מצב אמיתי של התוצר

- נכתב קוד Flutter למצלמה, זיהוי, תצוגה בעברית ובדיקת ביצועים.
- נבחר `YOLO26n` עם `ultralytics_yolo 0.6.16`: Core ML ב-iOS ו-LiteRT באנדרואיד.
- הורדת משקלי המודל תתבצע בהפעלה הראשונה בידי התוסף, והם יישמרו במכשיר. המשקלים אינם כלולים בחבילת המקור.
- נכתבו בדיקות Dart ומסלולי בנייה בענן; הן אינן תחליף להרצה על טלפון.
- בסביבת העבודה שבה נוצר הפרויקט לא היה Flutter, והורדתו נכשלה בגלל DNS. לכן טרם בוצעו `flutter analyze`, בדיקות Flutter, קומפילציה ל-iOS או Android, או ניסוי פיזי. אין עדיין קובץ התקנה מאומת.
- קובצי Android ו-iOS נוצרים מתוך Flutter באמצעות `tool/bootstrap.mjs`. זהו פרויקט מקור עם יצירה אוטומטית של קובצי הפלטפורמות, ולא תיקיית Xcode מוכנה מראש.

## מה יש במסך

הפעלה מפורשת של מצלמה אחורית, מסגרות זיהוי באמצעות התוסף, תרגום קטגוריות נפוצות לעברית, ציון ביטחון, קצב וזמן עיבוד מדווחים. אין הפעלת מצלמה אוטומטית בפתיחה.

בדיקת ביצועים אורכת 65 שניות: 5 שניות חימום ו-60 שניות מדידה. הדוח כולל חציון, אחוזון 95 ומקסימום של זמן העיבוד המדווח, דגימות גולמיות מוגבלות בכמות וסיבת סיום. אפשר להעתיק אותו ידנית ולהדביק בשיחה. הדוח נשמר בזיכרון בלבד; יש להעתיק לפני סגירת האפליקציה או התחלת בדיקה חדשה.

הקוד מפסיק את המצלמה ביציאה מהרקע, מתעלם מקריאות של מופע מצלמה ישן ואינו מציג נתונים ישנים כעדכניים אחרי הפסקת זרם התוצאות. המדידה נעצרת במקרה של הפרעה ומסומנת כחלקית.

## מה המדידה אינה אומרת

- זמן העיבוד מגיע מה-SDK. הוא אינו זמן מלא מחשיפה במצלמה ועד רטט/שמע.
- FPS מדווח אינו בהכרח FPS של המצלמה או הוכחה שכל פריים נותח.
- טרם נמדד מספר הפריימים שנפלו; בדוח ערך זה יהיה `null`.
- סופרים הופעות של קטגוריות בתוצאות, לא אנשים או עצמים ייחודיים. טרם נוסף מעקב עצמים.
- אין מדידת דיוק בלי סימון אמת, ואין מדידה אוטומטית של סוללה או טמפרטורה.
- שימוש בפועל ב-GPU/NPU דורש אימות בלוגים של המכשיר. הגדרת GPU היא בקשה בלבד.

## היכן הקבצים

- `lib/main.dart`: מסך הניסוי, הרשאות, מחזור חיים ודוח.
- `lib/domain/benchmark.dart`: איסוף נתונים וחישוב מדדים.
- `test/`: בדיקות נתונים ובדיקה שהמצלמה מתחילה כבויה.
- `tool/bootstrap.mjs`: יצירת פרויקטי Android ו-iOS והתאמתם.
- `tool/native_config.test.mjs`: בדיקות כלי ההגדרות.
- `codemagic.yaml`: בדיקות וקומפילציה לשתי המערכות ללא חתימת Apple.
- `docs/codemagic-testflight.yaml`: תבנית נפרדת לבנייה חתומה ולהפצת בטא.
- `docs/DEVICE_TEST.md`: נוהל בדיקה על מכשיר אמיתי.
- `docs/STATUS.md`: מה נבדק ומה עדיין חסום.

## הכנה בסביבה עם Flutter

נדרשים Flutter stable, Node.js 20 ומעלה, חיבור אינטרנט להורדת תלויות, וכלי הפלטפורמה הרלוונטית. ל-iOS נדרש Mac עם Xcode; הוא יכול להיות מחשב ענן. אין צורך להחזיק Mac בבית.

מתוך התיקייה הזאת:

```sh
node --test tool/native_config.test.mjs
node tool/bootstrap.mjs
flutter analyze
flutter test
flutter run --release
```

ב-Mac, לפני יצירת הפרויקט, מסלול הבנייה הנוכחי משתמש ב-CocoaPods:

```sh
flutter config --no-enable-swift-package-manager
node tool/bootstrap.mjs
cd ios
pod install --repo-update
```

`bootstrap` משמר את קוד האפליקציה והבדיקות, מגדיר Android API 23 ומעלה, compile/target SDK 36, ו-iOS 15 ומעלה, ומוסיף הרשאת מצלמה. רשימת התלויות הישירות מקובעת; לאחר הרצת `pub get` הראשונה יש לשמור גם `pubspec.lock` ו-`ios/Podfile.lock` במאגר, ולבחור גרסת Flutter מדויקת על בסיס הבנייה המוצלחת הראשונה.

## בנייה בענן בלי Mac אישי

1. מעבירים את תוכן התיקייה למאגר Git. `pubspec.yaml` ו-`codemagic.yaml` צריכים להיות בשורש המאגר. אם המאגר מכיל כמה פרויקטים, יש להגדיר ב-Codemagic את תיקיית העבודה הזאת.
2. מחברים את המאגר לחשבון Codemagic ומריצים ידנית `verify-mobile`.
3. המסלול יוצר את פרויקטי הפלטפורמות, מתקין תלויות, מריץ בדיקות ומקמפל Android ו-iOS. פלט Android הוא APK חתום בחתימת debug לניסוי, לא גרסת חנות.
4. פלט iOS במסלול הזה אינו חתום ואינו ניתן להתקנה באייפון. מטרתו לבדוק שהקוד מתקמפל לפני הגדרת חשבון Apple.
5. לאחר הצלחת הבנייה נרשמים ל-Apple Developer Program או משתמשים בחברות קיימת, מגדירים מזהה אפליקציה ייחודי ורשומת App Store Connect, ומחברים הרשאות חתימה ב-Codemagic.
6. רק אז משלבים את התבנית הנפרדת מתוך `docs/codemagic-testflight.yaml`, מעדכנים את שם האינטגרציה ואת שני מופעי מזהה האפליקציה, ובונים גרסה חתומה ל-TestFlight.
7. מתקינים TestFlight באייפון ומקבלים גישה לבטא. ייתכנו עיבוד ובדיקת בטא מצד Apple בהתאם לסוג הבודקים.

החשבונות, המזהים, החתימה והשירותים עדיין לא הוגדרו. לא בוצעה הרשמה, הוצאה כספית, העלאת מקור לשירות חיצוני או הפצה. מחיר וזמינות שירותי הענן ייבדקו לפני הפעלה. את מפתח Apple מזינים בשירות הבנייה המאובטח, ולא בקובץ מקור או בצ'אט.

## גבולות הגרסה

זהו ניסוי זיהוי עצמים בלבד, לא מערכת עזר מאושרת להליכה. אין עדיין מדידת מרחק, מפה תלת-ממדית, כיסוי 360, רטט, קול, ליווי מרחוק או החלטת מסלול. לא כל סכנה קיימת במחלקות המודל; ענפים, מדרגות ובורות דורשים עבודה ובדיקות ייעודיות. אי-זיהוי עצם אינו אומר שהמסלול פנוי.

האפליקציה מבקשת מצלמה בלבד. היא אינה מבקשת מיקרופון או מיקום. קוד הניסוי אינו שומר או מעלה תמונות. רשת נדרשת להורדת מודל ותלויות; לאחר הורדה יש לבצע בדיקת מצב טיסה גם לאחר הפעלה מחדש. התוסף החיצוני ותלויותיו צריכים לעבור בדיקת פרטיות כחלק מהכנת גרסה להפצה.
