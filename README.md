# VisionCane - אב־טיפוס תוכנה 0.2.0

אפליקציית Flutter לאייפון ולאנדרואיד, עם זיהוי מקומי, תיאור סביבה קולי ומצב נפרד לניסוי עומק. זו גרסת ניסוי מבוקרת, ולא אמצעי להכוונת הליכה עצמאית.

## הבסיס שנבדק

גרסה 0.1 נבנתה בהצלחה ב-Codemagic והורצה על Samsung Galaxy Tab S9 FE מדגם SM-X510, לפי דיווח המשתמש. דווח קצב עיבוד חציוני של כ-11.7 FPS. המשתמש אישר פעולה במצב טיסה; כיבוי Wi-Fi ופתיחה מחדש ללא רשת דורשים עדיין אימות מפורש. המדדים הם דיווחי SDK ואינם דיוק זיהוי או זמן תגובה מלא.

## מה נוסף ב-0.2

- תיאור קולי בעברית של עצמים ומיקומם בתמונה, כגון "כיסא במרכז התמונה". הקול כבוי כברירת מחדל.
- הקראה אוטומטית לזיהוי בציון 65% לפחות, שהופיע באופן חוזר במשך 700 מילישניות. מרווח של 3.5 שניות בין הקראות ו-12 שניות לפני חזרת קטגוריה באותו צד. זה אינו מעקב זהות אחרי עצמים.
- כפתור "תאר עכשיו" לתיאור עד שלושה זיהויים עדכניים בציון גבוה.
- שימוש בקול עברי מותקן. באנדרואיד קולות דורשי רשת או כאלה שלא ניתן לאמת כמקומיים אינם נבחרים. אין צורך בהרשאת מיקרופון.
- סינון סף בקוד האפליקציה ובקשת סנכרון עם הסף המקומי של התוסף לאחר טעינת המודל. שינוי סף מותר כשהמצלמה כבויה. הסף והמסגרות ייבדקו פיזית בבנייה החדשה.
- מצב נפרד לניסוי עומק, באמצעות מודל קטן מתוך הרשימה הרשמית הזמינה לפלטפורמה. מצב זה אינו פועל במקביל למזהה העצמים ואינו מפיק התרעת מרחק.
- דוח קצר להעתקה, ללא רשימת הדגימות הארוכה. דוח מלא זמין בנפרד.
- בניית app-release.apk במקום app-debug.apk לצורך בדיקות ביצועים. משתמש בחתימת הפיתוח של הפרויקט שנוצר; אין כאן חתימת production.
- נשמר תיקון התאימות ל-permission_handler בגרסה 12.0.1.

## מצב האימות

שבע בדיקות Node לכלי הגדרות הפלטפורמה עברו, ובדיקות התחביר של כלי ההכנה עברו. נכתבו בדיקות Flutter לסיכום הקצר, מדיניות הקראה, חלונות התייצבות וצינון, כיוונים, נתונים חסרים ומחזור מצלמה.

Flutter ו-Dart אינם מותקנים בסביבה המקומית. לכן גרסה 0.2 טרם עברה analyzer, בדיקות Flutter או קומפילציה, ואין APK חדש שנבדק במכשיר. הגרסה המותקנת אצל המשתמש עדיין 0.1. הבנייה הבאה בענן היא תנאי להתקנה. ייתכנו תיקוני אינטגרציה בקול, בסף ובתצוגת העומק.

## עדכון המאגר והתקנה

1. חלץ את הארכיון ופתח את visioncane_app.
2. במאגר visioncane ב-GitHub בחר Add file ואז Upload files.
3. גרור את תוכן התיקייה כולל תתי-תיקיות; אין להעלות את ה-ZIP ואין להוסיף תיקיית visioncane_app סביב התוכן בשורש המאגר.
4. שמור עם הודעת commit: Add prototype voice and depth experiments.
5. הפעל בנייה חדשה של main ב-Codemagic עם verify-mobile. אין לבצע Rebuild של commit ישן.
6. לאחר שכל הבדיקות והקומפילציה עברו, הורד והתקן app-release.apk בטאבלט.

אם העדכון נחסם בשל חתימה שונה, שמור דוח שחשוב לך, הסר את גרסת הניסוי הישנה והתקן את החדשה. הסרה מוחקת גם את המודלים השמורים, שיידרשו להורדה מחדש. אין צורך בתשלום ל-Apple כדי לבצע את הניסוי באנדרואיד.

## בדיקת הגרסה החדשה

בדוק קודם קול ומיקום בתמונה מול כיסא או מזוודה כשהמצלמה יציבה. בדוק שהשתקה ויציאה לרקע עוצרות את ההקראה. שמאל וימין הם ביחס לתמונה של המצלמה האחורית, ולא בהכרח לגוף.

לאחר מכן בחר ניסוי עומק כשהמצלמה כבויה. בפעם הראשונה נדרשת רשת למודל נפרד. בדוק את קרש הגיהוץ והרגליים שלו ממרחקים ידועים של 1, 2 ו-3 מטרים. מטרת הניסוי היא לבחון אם מפת העומק מבדילה את צורת המכשול מהרקע. אין להמיר צבע למטרים או להסיק שהמסלול פנוי.

בצע מדידה נפרדת של 65 שניות בכל מצב, ובמצב זיהוי מדוד גם עם קול כבוי. הזן SM-X510 והעתק סיכום קצר. לאחר הורדת המודלים והקול, בדוק פתיחה מחדש במצב טיסה עם Wi-Fi כבוי.

## קבצים ופיתוח

- lib/main.dart: ממשק, מצלמה, קול, הרשאות, מחזור חיים ודוחות.
- lib/domain/prototype.dart: כיוון בתמונה והתייצבות וצינון הקראות.
- lib/services/local_speech.dart: קול עברי מקומי.
- lib/domain/benchmark.dart: מדדי עיבוד, סיכום ודגימות אופציונליות.
- test/: בדיקות Flutter; tool/: הכנת קובצי הפלטפורמות ובדיקות Node.
- codemagic.yaml: מסלול הבנייה הפעיל.
- docs/codemagic-testflight.yaml: תבנית אופציונלית להפצה חתומה לאייפון; אינה מופעלת אוטומטית.

בסביבה עם Flutter stable ו-Node.js 20 ומעלה:

    node --test tool/native_config.test.mjs
    node tool/bootstrap.mjs
    flutter analyze
    flutter test
    flutter build apk --release

קובצי Android ו-iOS נוצרים באמצעות Flutter כדי להתאים ל-SDK המותקן. מסלול הענן משתמש ב-CocoaPods ל-iOS ומפיק פלט iOS ללא חתימה, שאינו ניתן להתקנה באייפון. לתהליך TestFlight נדרשת הגדרת חשבון וחתימה נפרדת. יש לשמור lockfiles מהבנייה המוצלחת ולבחור גרסת Flutter מדויקת לאחר אימות 0.2.

## מה עדיין חסר לאב־טיפוס התרעות מכשולים

יש לקבל ולכייל נתוני עומק מספריים, להגדיר את מסלול ההליכה ואת כיוון המצלמה ביחס לגוף, ולאסוף תרחישי אמת למדרגות, בורות, ענפים וכבלים. נדרש למדוד החמצות וזמן תגובה מלא לפני הפקת הוראות סכנה. שלב זה אינו ממומש ב-0.2. גם עומק ממודל ראייה עלול להחמיץ עצמים דקים.

## פרטיות ורישוי

הקוד אינו שומר או מעלה תמונות ואינו מבקש מיקום או מיקרופון. מודלי הראייה יורדים בפעם הראשונה ונשמרים במכשיר. דוחות מועתקים ידנית ונשמרים בזיכרון עד סגירה או מדידה חדשה. Ultralytics והתוסף כפופים לרישוי AGPL או למסלול מסחרי מתאים; יש להסדיר רישוי ובדיקת תלויות לפני הפצת מוצר. אין משקלי מודל בחבילת המקור.
